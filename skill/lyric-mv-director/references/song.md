# 歌：从 Suno v6 到一首能做 MV 的定稿

完整的写法在仓库 README 的“第一部分：用 Suno v6 写一首为画面准备的歌”。这里是给 Claude 用的核对表。

## 开工前问清楚

- 歌是定稿吗？MV 一旦开始做，歌不能再改：改一个字、换一次 Cover，所有逐字时间和拍点都要重做。
- 有没有分轨（人声、鼓、贝斯……）？有的话对齐和拍点都在分轨上做，精度高一截。
- 歌是什么套餐下生成的？Suno 的说明是：生成时是 Pro 或 Premier 订阅，歌归作者、可以商用；免费版生成的不能商用。Remix（Cover 等）出来的版本在部分说明里只许个人非商业使用。发布前让用户自己去看当前条款。
- 歌词表和实际演唱一样吗？Suno 常会多唱一遍、改一个字、加和声。照实际演唱做，差异记下来。

## 拿到歌以后

```bash
npx hyperframes audio assets/song.wav --only loudness,sections --json   # 响度、段落
```

- 记下整体响度（LUFS）和真峰值。成片的音轨直接用原歌，不要再压缩动态。
- 段落表从 `sections` 出发，再用耳朵校正（它给的段落边界不一定在小节线上）。
- 有分轨：人声轨给对齐，鼓轨给拍点（`tools/beatgrid.mjs` 的 `--low`/`--full` 都换成鼓轨的测量结果）。

## 歌里给画面留的东西

写段落表时专门标出来，这些是 MV 的“钩子”：

- 前奏：全片的第一个画面要在前奏里建立那个“物”。
- 每段副歌的第一个字：全片最强的冲击点。
- 间奏：没有字，画面做最大的动作。
- 停顿、断一拍：画面也停。
- 最后一段的长音：全片高潮落在这里。
- 歌里的采样、念白：画面要不要给它配字，单独决定。
